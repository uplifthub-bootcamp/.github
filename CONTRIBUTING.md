# Contributing to SecAware

SecAware is a training project. The instructor builds most of it in the open, and each issue is written as a lesson, so reading the issues and pull requests in order is a good way to learn.

## Take an issue

1. Pick an issue whose **Needs** are already merged, and assign yourself.
2. Create a branch from `main`, named after the issue, such as `api-05-register`.
3. Open a draft pull request within 2 working days, even if the work is unfinished.
4. Tick every acceptance criterion yourself, then mark the pull request ready.
5. If another student is available, ask them to follow the issue's steps and report what happened.
6. The instructor reviews the code and merges it.

Bootcamp members work on branches in these repos. If you are not a member, please fork the repo and open an issue first, so we can check the work is wanted.

## In your pull request

- Link the issue.
- Show the output that proves it works.
- Explain one decision you made and why.

## Stuck?

Each issue has a section on what to do when stuck. If you are still stuck after trying it, comment on your draft pull request with what you tried and what happened. Asking early is fine.

## Keep it safe

- Never commit passwords, tokens or `.env` files. If you do by accident, tell the instructor straight away, even if you have already removed it.
- Use real-looking but made-up data in examples, such as `learner@example.com`.
- Report security problems the way [SECURITY.md](SECURITY.md) describes, not in a public issue.
